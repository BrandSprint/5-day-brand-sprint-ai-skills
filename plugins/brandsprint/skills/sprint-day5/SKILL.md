# Sprint · Day 5 · Reality Check

Load `sprint-board` first; its rule, project folder, report format and placement rules apply in full. Open by reading `00 Project/project.md`, `00 Project/decisions.md` and the latest reports in `02 The Sprint/Day 2/`, `Day 3/` and `Day 4/`, including the Day 4 rehearsal, which this skill must not confuse with real feedback.

## When

The evening of Day 5, after the sessions, the ACES Map and the refinement. It can also run between the last session and the ACES exercise if the facilitator wants the sorting proposal before the room sorts; say in the report which it was.

## What this skill is for

Day 5 measures resonance. The team presents, the world reacts, the team decides what the reactions earn. The guide's guards: the deck shows before it explains, everyone writes before anyone speaks, customers go first. This skill does three things. It sorts the verbatim feedback into Amplify, Combine, Eliminate, Substitute as a proposal, with the quote behind every placement, so the room's own sort can be compared against it. It re-runs the Day 2 and Day 3 tests on the refined platform, because a change made at 16:00 on a Friday can break an ancestry that held on Tuesday. And it checks the Brand Canvas against every lock on the board: nothing on the canvas that is not on the board, nothing locked that is missing from the canvas.

## Frames to read

1. `Validation guide` and whatever frames hold the session notes: written first impressions (the two minutes on paper) and discussion notes, per audience. Ask the facilitator where they are if not obvious, and for the verbatim notes or transcript if the board holds only a summary.
2. `ACES Map`
3. The refined platform: `Brand Strategic Direction`, the three statements, `Core Brand Values`, `Rewrite Brand Values`, `Brand Archetypes`, `Look & Feel Slider`, `Tone of voice`, `Brand as a Person`
4. `Brand Canvas`
5. `Final Strategic Insights`
6. Any `Facilitator checks · …` frame

Report the inventory first, with the count of feedback items per audience and whether they are verbatim or summarised.

## Canvas layouts

ACES Map: four quadrants. Top-left Amplify, top-right Combine, bottom-left Eliminate, bottom-right Substitute. The adopted changes are usually a short list beside the map or on the Validation guide frame.

Brand Canvas: one page with the platform's elements in named fields (insight, purpose, vision, essence, positioning, values, archetype, look & feel, tone of voice, and the brand alive elements). Read every field by its label.

## Tests, in order

### T1 · The feedback itself
Per audience: were the first impressions written before discussion (separate stickies or notes from the discussion)? Are the notes verbatim or paraphrased by the team? Paraphrase is a finding, severity worth knowing, because the guide asks for the audience's words. Did customers go first? Did anyone see the deck before the session? Report what the notes show, or "not recorded".

### T2 · The sort, as a proposal
Place every feedback item in one ACES quadrant, with the quote and the audience behind it: Amplify (what landed and should be louder), Combine (two reactions that point at one change), Eliminate (what nobody understood or believed), Substitute (what the audience replaced with its own words). Then compare with the room's own sort: items the room placed differently, quoted, with the reason for the AI's placement. If the room put everything in Amplify, the guide's warning applies: the feedback wasn't critical enough; say so. If the AI's sort and the room's agree on the hard items, say that too. The room's sort stands; this is a second reading.

### T3 · Adopted changes
The list the room adopted: is each change traceable to a quote (feedback is input, not instruction, so a change with no quote behind it is the team's own, and a change with only one quote behind it from one person is thin)? Changes the feedback asked for that the room did not adopt: list them, no verdict; the room decides.

### T4 · The refined platform, re-tested
For every element the room changed on Day 5, re-run the test it belongs to: the Day 2 tests for purpose, essence and statements (three lengths of one decision, formula, only and best, copied not rewritten, competitor signature, ancestry), the Day 3 tests for values, archetype, sliders, tone and persona (decision test, upstream, coherence). Report only what changed and whether it still holds. A change that broke an ancestry is a finding, severity blocks the handover.

### T5 · The Brand Canvas against the board
Field by field: the canvas text against the lock on the board. Any difference, quoted both ways. A field on the canvas with no lock behind it: finding. A lock on the board missing from the canvas: finding. The canvas should read without tool names or day labels; any that leak are findings.

### T6 · The wrap-up
The four questions the guide asks the room to close on: what we made, what we heard, what changed because of it, what comes next. If the board or the notes record the answers, quote them; they become the opening of the handover documents. If not, list them as next steps for the facilitator to write from memory the same evening.

## Output

Write the report in the `sprint-board` format to `02 The Sprint/Day 5/report-<date>.md`. Readings: the proposed ACES sort with quotes, the comparison with the room's sort, and the canvas-against-board table. Opinion: whether the platform is ready for the handover, in two or three sentences, and the one change you would want the room to reconsider, if any. Next steps: what to settle before sprint-handover runs.

Closing question, exactly: "Place the top three on the board as black CHECK stickies in a frame 'Facilitator checks · Day 5'? The proposed ACES sort stays in the report unless you ask for it beside the map. yes / no / choose". Follow `sprint-board` for placement. Append the run to `decisions.md`.

## What this skill never does

Invent feedback, or use the Day 4 rehearsal as feedback. Adopt a change on the room's behalf. Edit the Brand Canvas. Write a replacement sentence for anything on the platform. Write to the board before the closing question is answered.
